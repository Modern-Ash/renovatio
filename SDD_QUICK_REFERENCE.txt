🎯 WHAT IS SDD?
───────────────────────────────────────────────────────────────────────────────
A structured 4-phase workflow for building features:
  1. SPECIFICATION   - Write WHAT you're building (user stories, requirements)
  2. DESIGN         - Design HOW you'll build it (data model, API contracts)
  3. IMPLEMENTATION - Code using TEST-FIRST approach (tests before code)
  4. VALIDATION     - Verify it meets spec and constitutional compliance


📦 RENOVATIO STACK

4. Implement test-first:

✅ FIVE CORE PRINCIPLES (CONSTITUTIONAL GATES)
───────────────────────────────────────────────────────────────────────────────

1. MODULE & PACKAGE FIRST
   ✓ Code goes into appropriate Maven module
   ✓ All modules have clear interfaces and Javadoc
   ✓ Modules follow: renovatio-provider-*, renovatio-shared, renovatio-web, etc.

2. TEST-FIRST (NON-NEGOTIABLE)
   ✓ Write tests BEFORE implementation
   ✓ JUnit 5 unit tests in src/test/java/*Test.java
   ✓ RestAssured integration tests in src/test/java/*IntegrationTest.java
   ✓ Tests must FAIL before implementation

3. API / CONTRACT-FIRST
   ✓ OpenAPI/Swagger specs for REST endpoints
   ✓ JSON-RPC 2.0 schemas for MCP tools
   ✓ Schemas defined BEFORE endpoint implementation

4. OBSERVABILITY & ERROR HANDLING
   ✓ Structured logging with @Slf4j + MDC correlation IDs
   ✓ Documented error codes (enum classes)
   ✓ Spring Boot Actuator metrics
   ✓ Audit trail for all mutations

5. VERSIONING & BACKWARD COMPATIBILITY
   ✓ Semantic versioning in pom.xml (MAJOR.MINOR.PATCH)
   ✓ Breaking changes require MAJOR version bump
   ✓ Migration plans documented for breaking changes

📊 EXAMPLE: COMPLETE WORKFLOW
───────────────────────────────────────────────────────────────────────────────

Feature: COBOL to Java Migration Tool

Step 1: Create feature
  $ bash .specify/scripts/bash/create-new-feature.sh \
    --short-name "cobol-migration" \
    "Implement automated COBOL to Java migration"
  → Branch: 005-cobol-migration
  → Spec:   specs/005-cobol-migration/spec.md

Step 2: Write specification
  Spec includes:
  • User Story 1 (P1): Parse COBOL → IR
  • User Story 2 (P2): Generate Java from IR
  • User Story 3 (P3): Expose via MCP tool
  • Requirements: FR-001, FR-002, etc.
  • Success criteria: SC-001, SC-002, etc.

Step 3: Plan design
  Outputs:
  • research.md         - Technical decisions
  • data-model.md       - CobolProgram, JavaGeneration entities
  • contracts/          - OpenAPI + MCP schemas
  • plan.md            - Implementation strategy

Step 4: Implement (test-first)
  For User Story 1 (Parse COBOL):
  
  a) Write test (must fail):
     @Test
     public void parsesCobolProgram() {
       CobolParser parser = new CobolParser();
       CobolIR result = parser.parse(cobolCode);
       assertThat(result).isNotNull();
     }
  
  b) Implement code (make test pass):
     @Component @Slf4j
     public class CobolParser {
       public CobolIR parse(String code) {
         MDC.put("correlationId", UUID.randomUUID().toString());
         log.info("Parsing COBOL");
         return parseUsingProLeap(code);
       }
     }
  
  c) Add error codes:
     public enum CobolParseError {
       INVALID_SYNTAX("COBOL_001", "Invalid COBOL syntax");
     }
  
  d) Run tests:
     $ mvn test
     $ mvn verify

Step 5: Create PR
  ✓ All tests passing
  ✓ Constitution compliance verified
  ✓ Code reviewed by 2+ maintainers

💡 KEY CONCEPTS
───────────────────────────────────────────────────────────────────────────────

USER STORIES:
  Independent slices of functionality:
  • P1 (Critical):    MVP - must deliver value
  • P2 (Important):   Significant feature addition
  • P3 (Nice-to-have): Polish and enhancements
  
  Example:
  • P1: Parser that converts COBOL to IR
  • P2: Code generator that produces Java from IR
  • P3: MCP tool to expose migration via agents

TEST-FIRST:
  1. Write test (must fail initially)
  2. Run test → FAILS ❌
  3. Implement code
  4. Run test → PASSES ✅

OBSERVABILITY:
  Every feature MUST include:
  • Logging:    @Slf4j + MDC with correlation IDs
  • Error codes: Documented enum (e.g., MigrationError.PARSE_ERROR)
  • Metrics:    Spring Boot Actuator counters/timers

MCP COMPLIANCE:
  If exposing tools:
  • JSON-RPC 2.0 schema (input/output specs)
  • Tool discovery endpoint
  • Error mapping to standard codes
  • Documentation and examples


❓ TROUBLESHOOTING
───────────────────────────────────────────────────────────────────────────────

Q: Tests are passing before I implement anything
A: You're writing tests AFTER code. Remember: write test, it FAILS, then implement.

Q: MCP schema validation fails
A: Validate JSON syntax: cat schemas/MyTool.json | jq .
   Check required fields: name, description, inputSchema, outputSchema

Q: Maven build failing due to missing dependency
A: Add to pom.xml and rebuild: mvn clean install

Q: Don't understand which module to put code in
A: See docs/SPEC_DRIVEN_DEVELOPMENT.md → "Renovatio-Specific Considerations"
