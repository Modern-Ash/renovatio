# Renovatio 0.3.0-alpha.1 Release Plan

## Candidate Policy

The release candidate SHA must be selected from `main` after required
dependencies are merged. The tag must be created only from that approved SHA.

## Required Gates

- Dependency gate: AC-01, AC-02, AC-03, AC-07, AC-09 and AC-10 complete.
- License gate: repository license approved and present.
- Build gate: full clean build and test matrix pass.
- Reference path gate: COBOL-to-Java quick start passes from clean clone.
- Security gate: secret, PII, dependency/license and generated-artifact scans
  pass.
- Supply-chain gate: SBOM, checksums, provenance and signatures produced.
- Approval gate: Spec Owner approves the release-readiness report.

All gates above remain required for publication. The candidate package satisfies
release planning and review inputs; it does not authorize tagging by itself.

## Publication Outputs

- Git tag: `v0.3.0-alpha.1`
- GitHub Release notes
- SBOM
- Checksums
- Build provenance
- Signatures
- Capability matrix
- Release-readiness report

## Rollback

If any gate fails before publication, do not publish the tag. If a published
artifact is found to be invalid, mark the GitHub Release as withdrawn and create
a follow-up remediation issue before any replacement release.
