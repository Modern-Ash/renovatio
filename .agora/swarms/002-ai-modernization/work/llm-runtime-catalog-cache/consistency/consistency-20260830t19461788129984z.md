# Consistency review

The supplied duplicate specification artifacts contain identical current content and do not conflict. The plan, threat model, catalog, implementation, and chronological test reports broadly align, but material coverage gaps remain.

## Blocking findings

- **Cache-first behavior contradicts the specification.** `LlmEnrichmentCli.run()` constructs the provider before loading and checking committed cache authority. The Anthropic path therefore requires `ANTHROPIC_API_KEY` even for a valid cache hit. This contradicts the specification and threat model requirement that a hit return without constructing a provider or requiring credentials. The recorded committed-hit evidence uses `offline-fake`, so it does not cover this production path.
- **Governed promotion verification is not implemented as claimed.** No Maven/build step generates the index exclusively from `git ls-tree HEAD` while verifying Commit A/B/C, owner approval, and Agora evidence. Runtime code trusts a committed manifest and checks field equality plus syntactic commit/reference formats; tests use fabricated commit hashes and an invented `repo://.agora/` reference. This contradicts the specification and overstates the promotion-proof claims in the reports.
- **Annotated-IR semantic validation is missing.** Provider output validation never invokes the accepted `AnnotatedCobolValidator`; `annotated-ir-reference.v1` only performs a top-level field-name/sub-string check and is effectively inactive for the published output schemas. This leaves the specification’s required final semantic-validation stage uncovered.
- **Production attribution finalization is not fail-closed end to end.** The gateway treats writing result JSON to stdout as successful finalization. A later failure by Agora to persist the completed tool-run cannot trigger runtime quarantine, contrary to the specified finalization-failure behavior. Tests cover only an injected sink failure inside the process.
